# SQLAlchemy 2.0 ORM

SQLAlchemy 2.0 standardizes a fully-typed declarative API (`Mapped[T]`, `mapped_column`), a unified Core/ORM execution model (`session.execute(select(...))`), and first-class async via `AsyncEngine`/`AsyncSession`. This skill covers idiomatic 2.0 usage; do not write 1.x patterns like `Column(...)` class attributes, `Query` API, or `session.query(Model)`.

## Use this skill when

- Defining ORM models with `Mapped[]` annotations and `mapped_column`
- Choosing relationship loading: `selectinload`, `joinedload`, `subqueryload`, `raiseload`, `lazy="raise"`
- Writing async code with `AsyncEngine`, `async_sessionmaker`, `AsyncSession`
- Setting up Alembic for autogenerated migrations against the declarative metadata
- Using `select()`, `insert()`, `update()`, `delete()` against ORM entities (2.0 style)
- Avoiding N+1 queries and detached instance errors

## Do not use this skill when

- The project is locked on SQLAlchemy 1.4 legacy `Query` and cannot upgrade
- You only need a thin SQL builder; use Core directly without ORM
- You want a different ORM (Django ORM, Tortoise, Prisma)

## Core concepts

Models inherit from a `DeclarativeBase` subclass and declare columns as typed attributes: `id: Mapped[int] = mapped_column(primary_key=True)`. The 2.0 execution model is `session.execute(select(...)).scalars()`; the legacy `session.query(...)` is discouraged. Async uses `AsyncSession` with `await session.execute(...)` and explicit `await session.commit()`; lazy attribute access on async sessions raises unless eagerly loaded.

## Quick start

```python
# pip install "sqlalchemy[asyncio]>=2.0" asyncpg alembic
from datetime import datetime
from sqlalchemy import ForeignKey, String, select
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column, relationship, selectinload
from sqlalchemy.ext.asyncio import async_sessionmaker, create_async_engine, AsyncSession

class Base(DeclarativeBase):
    pass

class User(Base):
    __tablename__ = "users"
    id: Mapped[int] = mapped_column(primary_key=True)
    email: Mapped[str] = mapped_column(String(255), unique=True)
    created_at: Mapped[datetime] = mapped_column(default=datetime.utcnow)
    posts: Mapped[list["Post"]] = relationship(back_populates="author", lazy="raise")

class Post(Base):
    __tablename__ = "posts"
    id: Mapped[int] = mapped_column(primary_key=True)
    author_id: Mapped[int] = mapped_column(ForeignKey("users.id"), index=True)
    title: Mapped[str]
    author: Mapped[User] = relationship(back_populates="posts")

engine = create_async_engine("postgresql+asyncpg://user:pw@localhost/app", echo=False)
Session = async_sessionmaker(engine, expire_on_commit=False)

async def list_users_with_posts() -> list[User]:
    async with Session() as s:
        stmt = select(User).options(selectinload(User.posts)).order_by(User.id)
        result = await s.execute(stmt)
        return list(result.scalars())
```

## Key patterns

### Typed columns
- `Mapped[int]` is NOT NULL; `Mapped[int | None]` is nullable. The annotation drives the column nullability.
- Use `mapped_column(String(255))` to set length; bare `Mapped[str]` infers `String` without length (problem on MySQL).
- `mapped_column(server_default=func.now())` puts the default in the DB; `default=...` is Python-side only.

### Loading strategies (avoid N+1)
- `selectinload`: separate `IN (...)` query per relationship. Best default for collections.
- `joinedload`: single SQL with `LEFT OUTER JOIN`. Best for many-to-one or one-to-one; can cartesian-explode on collections.
- `subqueryload`: separate query using a subquery; older, prefer `selectinload`.
- `raiseload` / `lazy="raise"`: turn accidental lazy loads into errors—use in async code and tests.

### Async session lifecycle
- Always `async with Session() as s:` to get a clean session; never share an `AsyncSession` across tasks.
- Set `expire_on_commit=False` when returning ORM objects from a function—otherwise attribute access after commit triggers a refresh that needs an open session.
- Lazy attribute access (`user.posts`) without eager loading triggers implicit IO; in async that raises `MissingGreenlet`. Eager-load with `.options(selectinload(...))` or call `await session.refresh(user, ["posts"])`.

### 2.0-style writes
```python
from sqlalchemy import update, delete
async with Session.begin() as s:
    s.add(User(email="a@b.com"))                       # INSERT
    await s.execute(update(User).where(User.id==1).values(email="x@y.com"))
    await s.execute(delete(Post).where(Post.author_id==1))
```

### Alembic
```bash
alembic init -t async migrations
# edit env.py: target_metadata = Base.metadata, configure async engine
alembic revision --autogenerate -m "add users"
alembic upgrade head
```
- Always review autogenerated migrations; Alembic misses `CHECK` constraints, server-side defaults changes, and column type changes on some dialects.
- Use `op.execute(...)` for data migrations; do not import ORM models—import a snapshot or use Core tables.

### Hybrid properties and computed columns
- `@hybrid_property` for attributes that work both in Python and SQL.
- `mapped_column(Computed("price * qty"))` for DB-side generated columns.

## Common pitfalls

- Writing 1.x `Column(Integer, primary_key=True)` class attributes in a 2.0 codebase—works, but loses typing and mixes styles. Use `Mapped[int] = mapped_column(primary_key=True)`.
- Using `session.query(Model)` instead of `select(Model)` in 2.0 code.
- Accessing relationships on an async session result without eager loading → `MissingGreenlet` / `DetachedInstanceError`.
- Forgetting `expire_on_commit=False` and getting attribute-access IO after the session closes.
- Putting `default=datetime.utcnow` (callable) vs `default=datetime.utcnow()` (called once at import); the parentheses matter.
- Letting Alembic autogenerate without reviewing—it can drop unrecognized custom types or generate non-trivial column renames as drop+add (data loss).
- Sharing one `AsyncSession` across concurrent tasks; sessions are not thread- or task-safe.
